# 11. Estratégia de Testes

## 🧭 Princípio

Testar para ganhar confiança, não para acumular execícios.

## 🧱 Camadas Sugeridas

- **Testes do domínio/regra de negócio:** verificam comportamento de regras como consumo de insumo, restrições de empréstimo, cálculos de relatórios.
- **Testes de fluxo básico:** verificam que um registro, devolução, manutenção ou relatório funciona de forma coerente.
- **Testes de integração do módulo:** verificam que módulos ligados se comportam de forma consistente.
- **Verificação manual/usabilidade:** confirma que o sistema é usado de maneira realista.

## 🔁 O que deve ser protegido primeiro

- Regras de negócio críticas
- Restrições que invalidam um fluxo (ex.: máquina fixa não pode ser emprestada)
- Contas e saldos que afetam decisões
- Relatórios que têm base de dados específica

## 🧪 Como abordar cada sprint

- Definir casos principais antes de implementar
- Testar o caminho feliz e casos mais prováveis de erro
- Validar efeitos cruzados entre módulos quando relevante
- Registrar o que foi testado e o que ainda precisa ser

## 🧼 Boas práticas de teste

- Nomear o que está sendo testado de forma legível
- Evitar testes dependentes de detalhes frágeis
- Priorizar clareza para quem vai ler depois
- Tratar testes como parte do entregável, não como "módulo extra"

## ⚠️ O que não compensa

- Testar tudo com igual profundidade sem foco de risco
- Escrever testes que só validam coisa que já é óbvia
- Ignorar fluxos que não são "tela principal" mas são críticos

> **Dica:** uma estratégia de testes só ajuda se for usada para apoiar decisões.
