# 10. Exemplos de Definição de Pronto (DoD)

## ✅ Definição Geral de Pronto

Um item é pronto quando:

- Cumpre o objetivo do backlog/sistema
- Pode ser testado de forma clara
- Não deixa contornos manuais implícitos para uso
- Foi revisado e não introduz regressão óbvia

## ✅ DoD por Tipo de Entrega

### Cadastro
- Permite criar, editar e listar o cadastro de forma coerente
- Validações claras e mensagens úteis
- Dados salvos de maneira consistente
- Acesso e perfis adequados

### Registro Operacional
- Registra o que deve acontecer
- Vincula os elementos esperados (máquina, técnico, cliente, insumo, etc., quando aplicável)
- Não quebra regras de negócio como empréstimo de máquina fixa
- Gera efeito esperado nos relatórios ou saldos, quando houver

### Relatório
- Usa dados válidos e não dados inventados
- Mostra informações esperadas e coerentes
- Funciona para os filtros/periódos pretendidos
- É possível verificar manualmente em casos simples

### Autenticação e Permissão
- Só permite acesso conforme o perfil
- Bloqueia ações não permitidas
- Não expõe informações indevidas por perfil

## 🧰 Checklist Rápido de Pronto

- [ ] O objetivo do item está claro
- [ ] Foi testado em casos principais
- [ ] Foi considerada a separação de módulos
- [ ] Regra de negócio crítica não foi "contornada"
- [ ] Outros fluxos possivelmente afetados foram verificados
- [ ] Revisão feita e feedback aplicado

## ⚠️ O que não é suficiente

- "Apenas aparece na tela"
- "Funciona com um caso manual"
- "Espera que o usuário entenda o erro"
- "A regra fica na interface sem proteção"

> **Dica:** se não conseguir definir pronto de forma curta, significa que o item ainda não foi acabado de decompor.
