# 14. Roteiro de Revisão de Código

## 👀 O que revisar

- Se o código atende o objetivo pretendido
- Se a responsabilidade está no lugar certo
- Se há duplicação evitável
- Se regras importantes estão protegidas
- Se o nome e a leitura são claros

## 🧩 Perguntas Rápidas

- Esse arquivo faz mais do que deveria?
- Essa regra ficou em um lugar sensato?
- Se eu mudar isso, o que mais pode quebrar?
- Isso fica mais fácil ou mais difícil de manter?

## ✅ Sinais Positivos

- Função/module com propósito claro
- Dados de entrada e saída coerentes
- Separação entre regra e detalhe de interface, quando aplicável
- Testes ou verificações nos pontos críticos

## 🚨 Sinais de Alerta

- Lógica grande sem divisão
- Múltiplos módulos dependendo de detalhes internos
- Regras duplicadas ou espalhadas
- Proteção de perfil/segurança apenas no visual

## 📝 Como dar feedback

- Ser direto, mas útil
- Questionar antes de impor quando possível
- Priorizar regras e risco sobre gosto estético
- Sugerir como melhora, não apenas apontar o problema

## 🔁 A revisão dentro do projeto

- Não esperar o "termo final" para revisar
- Revisar antes de considerar pronto
- Registrar decisões que importam para depois

> **Dica:** revisão útil resolve ambiguidade, não só estética.
